Omnimud user manual

Omnimud is a MUD client for Windows, designed from the start to be used with a screen reader. This manual describes version 2.

Keys are written like this: Ctrl+K. Commands that you type in the game are written like this: cls.

1. Introduction and requirements

A MUD is a text-only online role-playing game. Omnimud connects to the MUD, shows what the game writes and sends what you type.

What makes Omnimud different:

  • Everything works from the keyboard. Every box has a label and an accessible name.
  • Every shortcut is also in the menus, so you can discover them by walking the menus.
  • The text of the MUD is announced through UI Automation, which any modern screen reader understands. The JAWS and NVDA libraries remain as a fallback.
  • The cursor of the Received box does not move when new text arrives. You can review earlier text while the MUD keeps writing.
  • Conversations are copied to a separate box, Messages, and you can review them with Ctrl+1 to Ctrl+0 without moving the focus.
  • It has aliases, triggers with Lua scripts, paths, movement mode, MSP sound, GMCP, session logs and options at three levels.
  • It is portable: all the data lives in a data folder next to the program.
  • The interface is available in Spanish and English.

Requirements

  • Windows 10 (version 1709) or later, 64-bit.
  • You do not need to install .NET: the program carries it inside.
  • A screen reader if you need one: NVDA, JAWS or Narrator.
  • An internet connection to play. Omnimud does not need administrator rights.

2. Installation and first steps

Installation

Omnimud is downloaded from the Releases page on GitHub: https://github.com/kastwey/omnimud/releases. There are two ways to install it:

  • Portable zip, named Omnimud-<version>-win-x64-portable.zip. Unzip it into a folder where you have write permission, for example inside Documents or on a USB drive. Then run Omnimud.exe.
  • Per-user installer, if the release offers one. It installs the program for your user only and does not ask for administrator rights.

In both cases, all your data is stored in the data folder next to Omnimud.exe. Nothing is written to the Windows Registry.

Do not unzip the file inside "Program Files": programs cannot write there. More details in Portability.

First steps

  1. Run Omnimud.exe. The launcher opens, with the focus on the "MUDs and characters" tree.
  2. Press Ctrl+N to add a MUD. Type its name, its host and its port, and press OK.
  3. Press Ctrl+Shift+N to add a character to that MUD. Type its name and, if you want, its password.
  4. With the character selected in the tree, press Enter. The game window opens and connects.
  5. Type in the "Text to send" box and press Enter to send each command.
  6. Press F1 at any time to open this manual.

If you only want to try a MUD without saving it, use quick connect with Ctrl+Q.

The language of the interface is chosen automatically: Spanish if Windows has Spanish installed, English otherwise. You can change it in the global options.

3. The launcher

The launcher is the start window. From it you manage your MUDs and characters, connect, import and export. You can have several game windows open at the same time; the launcher stays open.

Every action of the launcher is in four places at once: the buttons, the main menu, the context menu of the tree and the keys. Use whichever you prefer.

The tree of MUDs and characters

  • The tree is called "MUDs and characters". You reach it with Alt+M.
  • Each MUD is a top-level node. It is read with its name, host and port, for example "My MUD (mud.example.org:23)".
  • Inside each MUD are its characters. The default character is read with the text "(default)".
  • The up and down arrows move through the nodes. The right arrow expands a MUD and the left arrow collapses it.
  • After adding, editing or removing something, the selection is kept. When you remove an element, its neighbour becomes selected.

Keys inside the tree:

  • Enter: connect. On a character, it connects with that character. On a MUD, it connects with its default character; if it has none, it connects to the MUD without a character. A double click on a character also connects.
  • F2: edit the selected MUD or character.
  • Del: remove the selected element, after a confirmation. Removing a MUD also removes its characters, with their aliases, triggers and paths.
  • Insert: add a sibling of what is selected. On a character it adds another character; on a MUD it adds another MUD.
  • The Applications key or Shift+F10: opens the context menu next to the node.

At the bottom there is a status line, with the accessible name "Status". It tells the result of the last action, for example "MUD My MUD added."

Buttons

  • Connect (Alt+C). It is the default button of the window.
  • Quick connect… (Alt+Q).
  • Add MUD… (Alt+A).
  • Add character… (Alt+T). If there is no MUD yet, the program asks you to add one first.
  • Edit… (Alt+E).
  • Remove (Alt+R).
  • Set as default (Alt+D). Only enabled on a character that is not the default one yet.

The buttons that cannot be used with the current selection are disabled.

Menus

  • Connect (Enter in the tree).
  • Quick connect… (Ctrl+Q).
  • Add MUD… (Ctrl+N).
  • Add character… (Ctrl+Shift+N).
  • Edit… (F2 in the tree).
  • Remove (Del in the tree).
  • Set as default (Ctrl+D).
  • Clear default. Only enabled on the default character.
  • Exit (Alt+F4).

Tools menu (Alt+O):

  • Global options… (Ctrl+O). See Options.
  • Message rules… (Ctrl+R). See Message rules.
  • Import… (Ctrl+I).
  • Export MUD… (Ctrl+E).
  • Export character… (Ctrl+Shift+E). See Import and export.
  • Check for updates now. See Updates.
  • Check for updates on startup. It is a check box inside the menu and it is off by default.
  • Personal information… See Personal information.

Help menu (Alt+H):

  • User manual (F1). Opens this manual in the browser, in the language of the interface.
  • Lua scripting reference. Opens the file API_LUA.md, which is written in Spanish.
  • Send suggestion…
  • Report an error… See Suggestions, errors and privacy.
  • About Omnimud… Tells the installed version.

Context menu

It opens with the Applications key, with Shift+F10 or with the right mouse button. From the keyboard it appears next to the selected node. Its content depends on the node:

  • On a MUD: Connect, Edit MUD…, Delete MUD, Add character…, Export MUD…
  • On a character: Connect, Edit character…, Delete character, Set as default, Export character… If the character already is the default one, that entry is shown checked and disabled: that way the state can be heard.
  • With an empty tree, or with a right click on the empty area: Add MUD…, Import…

4. Quick connect

Quick connect (Ctrl+Q in the launcher) connects to a server without saving it as a MUD. The dialog has these fields:

  • Server: the address or the domain. It cannot contain spaces.
  • Port: a number between 1 and 65535.
  • Use TLS (encrypted connection).
  • Validate the server certificate. It can only be changed while TLS is checked.
  • Encoding. utf-8 by default.
  • The Connect button.

The first time, server and port are empty. Afterwards the dialog remembers the last connection used. When you enter each box, its text is selected so that you can type over it.

A quick connect session has no saved MUD or character. Because of that, in such a session:

  • There are no aliases, triggers or paths: F5, F6 and F7 tell you that a session with a character is required.
  • There are no directions or movement keys of its own: those dialogs tell you that a saved MUD is required. Movement mode works with the default commands.
  • There is no automatic login and there are no message rules.
  • F9 opens the global options.

5. MUDs and characters

A MUD stores the connection data of a game. A character always belongs to a MUD. Aliases, triggers and paths belong to each character. The directions for paths and the message rule set belong to each MUD.

Adding or editing a MUD

The "Add MUD" dialog has these fields:

  • Name. Required. Two MUDs cannot have the same name.
  • Host (address or domain). Required, without spaces.
  • Port. Between 1 and 65535. 23 by default.
  • Use TLS (encrypted connection). Check it only if the MUD offers an encrypted port. TLS 1.2 or 1.3 is used.
  • Validate the server certificate. It can only be changed while TLS is checked, and it comes checked. If the certificate of the MUD is not valid, the connection fails and the message explains why. Uncheck it only if you trust that server, for example if it uses a self-signed certificate.
  • Encoding. The character encoding of the MUD, in both directions. The list offers utf-8, iso-8859-1, windows-1252 and ascii. You can also type another valid name, for example iso-8859-15. If accented letters look wrong, try another encoding.
  • Message rule set. Choose which rule set carries the conversations of this MUD to the Messages box. "(None)" means no rules. See Message rules.
  • Sound folder, with the Browse… button. Empty means the default folder for this MUD: data\sounds\name of the MUD. If you type a folder, it must exist.
  • Save command. Used by F3 and when the window closes. If it is empty, F3 is disabled.
  • Quit command. Used by F4 and when the window closes. If it is empty, F4 is disabled.
  • Login script. See the next section.

If something is not valid, a message appears and the focus goes to the field that must be corrected.

Login script

These are the commands Omnimud sends right after connecting, one per line. Empty lines are ignored. There are two placeholders:

  • %character is replaced with the name of the character.
  • %password is replaced with its saved password.

If you leave the script empty, Omnimud sends the name of the character and then its password, if one is saved. If you connect to the MUD without a character, it sends nothing.

An example for a MUD that first asks whether you want colours:

n
%character
%password

Lines that contain %password are never written to the session log.

Adding or editing a character

  • Name of the character. Required. It cannot be repeated inside the same MUD.
  • MUD. The MUD it belongs to.
  • Remember password. A check box.
  • Password. It is typed hidden.

How the password is handled:

  • It is stored encrypted and is never shown, not even as dots.
  • When you edit a character that already has a password, the box is empty. Leave it empty to keep the password, or type a new one to replace it.
  • To make Omnimud forget the password, uncheck "Remember password" and accept. The saved password is deleted.
  • If you check "Remember password" on a character without a saved password, you have to type one.
  • Passwords are never exported and do not work on another computer. See Portability.

The default character of a MUD is the one used when you press Enter on the MUD node. Set it with Ctrl+D and clear it with "Clear default" in the File menu.

6. The game window

Each connection has its own window. The title is "Omnimud - " followed by the character and the MUD. When it opens, the window connects by itself.

The boxes and the button

The tab order is this:

  1. Text to send (Alt+T, and also Ctrl+K from anywhere). Here you type the commands.
  2. Received (Alt+R). All the text of the MUD, with its colours. It is read-only.
  3. Messages (Alt+M). The conversations: channels, tells, what other players say. It is filled by the message rules and by GMCP. It is read-only.
  4. A button that closes the window. It is called Cancel while connecting, Disconnect while connected and Close otherwise.

Things worth knowing about Received and Messages:

  • The cursor does not move when new text arrives, unless it already was at the end. You can read backwards calmly. This behaviour can be changed in the options.
  • When one of these boxes gets the focus, the screen reader says its name and only the line where the cursor is.
  • If you start typing inside Received or Messages, the letter is not lost: the focus moves to "Text to send" and the letter is typed there.
  • Received keeps a maximum number of lines (10,000 by default). The oldest ones are removed.
  • The Messages box can be hidden from the View menu.

Status bar

It is at the bottom of the window and has three parts:

  • Connection status: "Connecting to…", "Connected as…", "Disconnected from…" or "Offline mode". While you record a path it says "Recording path". A Lua script can also write here.
  • Time connected, for example "1 hour, 5 minutes, 12 seconds."
  • Messages status: "No messages" or the time of the last message. While you move through the Messages box it shows, for a few seconds, the time of the message where the cursor is.

Typing and sending

  • Enter sends what you typed and empties the box.
  • Enter on an empty box repeats the last command. If you have not sent any command yet, it sends a blank line.
  • Shift+Enter or Ctrl+Enter insert a line break. That way you can prepare several lines and send them together with Enter. On an empty box, these keys send a blank line, without repeating anything.
  • Inside a text of several lines, the up and down arrows move between its lines and the screen reader reads them.
  • Escape deletes what you typed.
  • You can also send several commands in one line, or repeat one several times, with the special characters. They are off by default.

Before leaving for the MUD, what you type goes through this order: paths (_name), aliases, command triggers, internal commands and, last, command stacking and repetition.

Command history

  • Ctrl+Up arrow and Ctrl+Down arrow always browse the history.
  • Up arrow and Down arrow browse it too, when they are not moving the cursor inside a text of several lines and when movement mode is not using them.
  • Each step through the history plays a click. The recalled command is selected: if you type, you replace it.
  • When you go down past the most recent command, the box becomes empty.
  • A command equal to the previous one is not stored twice. The history keeps 50 commands by default; this can be changed in the options.

Password mode

When the MUD announces that it is going to ask for a password (with the Telnet ECHO option), the input box changes:

  • It is renamed "Password", and what you type is neither shown nor read.
  • What you send does not enter the history, is not written to the log, does not go through aliases or triggers and does not count as "last command".
  • The history and the movement keys are disabled.

When the MUD has finished asking for the password, the box becomes "Text to send" again.

Context menu, find and links

In Received and in Messages, the Applications key, Shift+F10 or the right mouse button open a context menu. From the keyboard it opens next to the text cursor. It contains:

  • Copy (Ctrl+C), Select all (Ctrl+E), Find… (Ctrl+B) and Find next (Ctrl+S).
  • Only in Received, and only if the MUD offers them: the sections of the Actions menu, such as Inventory and Exits.

Find works on the box that has the focus, Received or Messages. The dialog has the text to find, the "Match case" check box and the direction, Down or Up. If you had text selected, it is already typed in. The text found becomes selected. "Find next" repeats the last search; if there are no more matches a warning sound plays.

Links: place the cursor on a web address inside Received or Messages and press Enter. It opens in the browser and a sound plays. Only http, https, ftp and mail addresses are opened. If there is no link under the cursor, you hear a beep.

Menus of the game window

The menu bar is: Actions, Game, Edit, View, Tools, Help.

  • Actions (Alt+A). It only appears while the MUD offers actions through GMCP. See GMCP.
  • Game (Alt+G): Save game (F3), Quit the game (F4), Reconnect, Close window.
  • Edit (Alt+E): Copy, Cut, Paste, Select all, Undo, Find…, Find next, Clear received text. They act on the box that has the focus. Cut, Paste and Undo only work in "Text to send"; Find only works in Received and Messages.
  • View (Alt+V): Go to text to send (Ctrl+K), Enlarge received area (Ctrl++), Shrink received area (Ctrl+-), Reset sizes, and Hide messages panel or Show messages panel. Enlarge and shrink share the space between Received and Messages.
  • Tools (Alt+O): Movement mode (F2), Aliases (F5), Triggers (F6), Paths (F7), Silent mode (F8), Options (F9), Configure movement keys, Directions for paths, Mute screen reader (Ctrl+M) and Stop speech (Alt+S). The entries that are a switch are shown checked while they are on.
  • Help (Alt+H): User manual (F1), Lua scripting reference, Send suggestion…, Report an error…, About Omnimud…

Aliases, Triggers and Paths require a session with a character. When you close any of these dialogs, the changes are applied at once to the open session.

Disconnecting, reconnecting and closing

  • If the server closes the connection, the window does not close. The Reconnect button (Alt+N) appears and gets the focus. It is also in the Game menu.
  • When you close the window while connected, Omnimud asks for confirmation. Then it sends the save command and the quit command of the MUD, waits a moment so that you can see the farewell, and disconnects. Both things can be turned off in the options.
  • If the connection fails when the window opens, a message tells the reason. If the session has a character, Omnimud asks whether you want to open it in offline mode. In that mode nothing is sent to the MUD, but you can manage its aliases, triggers and paths.
  • If text arrives while the window is in the background, its taskbar button flashes. The text of the MUD is only announced by voice while the window is in the foreground.

8. Reading messages

You can review the Messages box from anywhere in the window, without moving the focus. Message number 1 is always the most recent one.

  • Ctrl+1 to Ctrl+9 read messages 1 to 9. Ctrl+0 on its own reads message 10. Both the top row digits and the numeric keypad work.
  • Digit concatenation: if you press another digit before 400 milliseconds have passed, the digits are joined. Ctrl+1 and right away Ctrl+5 read message 15. Hold Ctrl down and type the number. Up to three digits are accepted; a fourth digit beeps and cancels.
  • Escape cancels a half-typed digit sequence.
  • Ctrl+º reviews backwards. The first press reads message 1. Each further press, if it comes within 800 milliseconds, reads message 2, 3, and so on. After a pause it starts again at 1.
  • The screen reader says the number and the text, for example "3: Ann tells you: hello".
  • If that message does not exist, it says "There are no messages.", "There is only one message." or "There are only N messages."
  • Ctrl+F, with the focus in Messages, says the date and time of the message where the cursor is. With the focus in Received, it says those of the last message. If there is none, it says "Time not found."

These readings interrupt whatever the screen reader was saying.

9. Movement mode

Movement mode turns some keys into directions, so that you can walk without typing. Turn it on and off with F2. The screen reader says "Movement mode on." or "Movement mode off." The state is remembered for each MUD or character.

Type the command you want each key to send. Leave a box empty to disable that key. The "Restore defaults" button goes back to the commands of the table.

The keys belong to the character if the session has a character, and to the MUD if it has none. A character without keys of its own uses those of its MUD. The dialog tells you whose keys you are editing.

10. Silent mode and all_speak

In silent mode, Omnimud stops announcing by voice the text of the MUD and the messages. The text still arrives in Received and in Messages, and is still written to the log. It is useful for fights or for areas with a lot of text.

  • Turn it on and off with F8, or with the commands callate and hablar.
  • The replies of the client itself, for example the reply to calias, are always announced.
  • Reading with Ctrl+1 to Ctrl+0 keeps working.

The all_speak: marker. If a line of the MUD contains the text all_speak:, what follows it is announced by voice even in silent mode. The marker is never shown on screen nor written to the log. Some MUDs send it so that important things are not missed; you can also have your MUD emit it in the notices you care about, if the game allows that.

A Lua script can speak at any time with om.say, in silent mode too.

11. Muting the screen reader and stopping speech

  • Mute screen reader (Ctrl+M). Omnimud stops sending announcements to the screen reader: no text of the MUD, no messages, no Ctrl+1 readings. The screen reader still reads normally whatever you walk through with the cursor. When you turn it on it says "Screen reader announcements muted." and when you turn it off "Screen reader announcements enabled."
  • Stop speech (Alt+S). Cuts what the screen reader is saying at that moment and empties what is pending. It does not change any setting.

The difference with silent mode: F8 silences the text of the game but lets all_speak: and the replies of the client through. Ctrl+M silences everything.

hablarTurns silent mode off ("speak").
  • The alias, trigger and path commands require a session with a character.
  • If aliases and triggers call each other in a loop, Omnimud cuts it at ten levels and warns: "Too many nested commands".
  • Without a connection, commands for the MUD are not sent and the client says so.

13. Aliases

An alias is an abbreviation: you type a short word and Omnimud sends a longer action. Open them with F5 or with the calias command. They belong to each character.

How they work:

  • Only the first word of what you type is compared, exactly and case-sensitively.
  • The first word is replaced with the action. The rest of the line is kept. With the alias gc for get all from, typing gc corpse sends get all from corpse.
  • It is applied only once: an alias does not expand into another alias in the same word.
  • The command of an alias cannot contain spaces.
  • If command stacking is on, the action can hold several commands separated by the chosen character.

The "Aliases of" window has a list with the columns Command, Action and Enabled, and these buttons: Add, Edit, Remove, Enable or Disable, Sort by, Import, Export… and Close.

  • In the list: Insert adds, F2 or Enter edit, Del removes and Space enables or disables. The change is announced, for example "Alias gc disabled".
  • The Applications key opens a context menu with the same actions.
  • "Sort by" opens a menu with the columns. The chosen order is remembered for each character.
  • "Import" offers "From file…" and "From another character…". "Export…" saves all the aliases to an .omnimud file.

The alias editor has the fields Command and Action and the Enabled check box. It warns if the command already exists, and asks if another alias already performs that same action.

14. Triggers

A trigger reacts by itself when the MUD writes a given text. It can send a command, play a sound, hide the line or run a Lua script. Open them with F6 or with the triggers command. They belong to each character.

The trigger list

The "Triggers of" window works like the aliases one. Columns: Name, Pattern, Type, Action, Priority and Enabled. Besides the buttons of the alias list, it has Move up and Move down.

  • Alt+Up arrow and Alt+Down arrow move the trigger in the evaluation order. The screen reader says the new position.
  • Moving is only possible while the list is sorted by "Evaluation order", ascending. Otherwise the program tells you.
  • Space enables or disables the trigger.

Pattern types and wildcards

The "Trigger text" field is the text that fires the trigger. The "Pattern type" says how it is interpreted:

  • Literal text. It fires if the line contains that text. A ^ at the start requires the line to begin that way. A $ at the end requires it to end that way. With both, the line must be exactly that.
  • Wildcards %s %d %w. Normal text with gaps:
    • %s: any text, as short as possible.
    • %d: a number.
    • %w: one word, without spaces.
    • %%: a percent sign.
    • With a digit in the middle, a fixed length: %3d is exactly three digits.
    • ^ at the start and $ at the end anchor the line, as with literal text.
  • Regular expression. A .NET regular expression. The groups in parentheses are the captures. If the expression is badly written, or so slow that it could block the program, the editor does not accept it.

What the wildcards or the groups capture is used in the action as %1, %2, and so on. An example with wildcards:

Trigger text: ^%w tells you: %s
Action: tell %1 I cannot talk now, I am busy

The "Case sensitive" check box is unchecked by default.

Multiline, hide the line and priority

  • Multiline (evaluate the whole block). Unchecked, the trigger is evaluated against each complete line. Checked, it is evaluated against the whole block of lines that arrived together. In a multiline regular expression, ^ and $ still mean start and end of each line. With wildcards, the block is treated as one long line.
  • Hide the line. The line that fires the trigger is not shown, not announced and not written to the log. It only applies to line triggers: with Multiline checked, this check box is disabled.
  • Priority. A number from 0 to 1000; 50 by default. Triggers with a higher priority are evaluated first. With equal priorities, the order of the list decides.
  • Enabled. A disabled trigger is not evaluated.

Every trigger that matches fires: none stops the others. The text that the client itself writes, such as the replies to internal commands, does not fire triggers.

What the trigger does

The "What will it do?" list has four choices:

  • Send a command. The action is a single line. It goes through aliases, paths, internal commands, stacking and repetition, as if you had typed it. For several steps use the command stacking character or a Lua script.
  • Play a sound. Type the file name in "Sound" or choose it with Browse… wav, mp3 and ogg files work. A name without a path is looked up first in the sound folder of the MUD and then in the sounds folder of the program. A full path on your disk also works.
  • Both. Plays the sound and sends the command.
  • Lua script. The Action box is renamed "Lua script" and accepts several lines. Inside it, Tab indents and Ctrl+Tab leaves the box. When you accept, the script is validated; if it has an error, the message tells the line and the cursor goes to it. See Lua scripts.

The "Play sound" button plays the given file. This button does not look in the sound folder of the MUD, so to try a sound from that folder choose it with Browse…

Command triggers (@)

If the trigger text starts with @, the trigger does not look at the text of the MUD. It fires when you type that word as the first word of a command. It lets you create your own commands.

  • The trigger @heal fires when you type heal, or heal ann.
  • The words that follow are %1, %2, and so on. In Lua they are om.args, and the whole line is om.command.
  • The command you typed is not sent to the MUD.
  • The name cannot contain spaces. It is compared after aliases are applied, and it honours the case check box.
  • A command trigger is always literal text, cannot be multiline and does not hide lines. The editor disables those controls and explains it.
  • With -triggers they do not fire either.

The Test button

Type an example line in "Sample text" and press Test. The "Result" box says, and the screen reader announces:

  • "It matches." or "It does not match."
  • The captures, for example "%1 = Ann".
  • What it would do: "Would send: …", "Would play: …", "Would hide the line."
  • For a Lua script, the script really runs against a fake host, and the result lists each thing it would have done: send, display, say, add a message, set a variable. If it fails, it tells the error and its line.

The test never sends anything to the MUD.

15. Lua scripts

Triggers of the "Lua script" kind run Lua 5.2 code inside a safe environment. Everything the script can do is in the om table. The full reference, with examples, is in the file API_LUA.md, which is installed next to this manual. It is written in Spanish. It also opens from the Help menu, "Lua scripting reference".

An example for a trigger with the regular expression ^(\w+) tells you: '(.+)'$:

om.send("say Hello, " .. om.captures[1])
om.playsound("notice.wav")

The most used parts:

  • Data: om.line, om.block, om.lines, om.captures, om.args, om.command, om.mud.name, om.character.name.
  • Sending: om.send (as if you typed it), om.sendraw (straight to the MUD) and om.get (sends and returns the reply without showing it).
  • Showing and speaking: om.display, om.echo, om.say, om.message (adds to the Messages box), om.status (status bar), om.log, om.gag (hides the line).
  • Sound: om.playsound and om.stopsound.
  • Session variables: om.setvar, om.getvar, om.removevar, om.isset. Lua global variables do not survive from one run to the next; these do, for as long as the session lasts.
  • Time: om.sleep, om.countdown, om.timer, om.canceltimer.

Safety and limits:

  • A script cannot read or write files, use the network or run programs.
  • No script can hang the client: an endless loop is cut automatically. There are limits on instructions, time and memory.
  • An error in a script never closes Omnimud. It is shown in Received with the name of the trigger and the line number.
  • The same trigger does not overlap with itself: if it fires again while its script is still running, that firing is dropped.

Message rule sets of the Lua script type use the same language with a stricter contract.

16. Paths and directions

A path is a saved route: a list of directions that Omnimud sends in one go. Paths belong to each character. For them to work, the MUD needs a dictionary of directions.

Directions of the MUD

Tools menu, "Directions for paths". A saved MUD is required. Each direction has three pieces of data:

  • Direction: the full command that is sent, for example north.
  • Abbreviation: a single character, which cannot be a digit. It is what you write inside the path, for example n.
  • Opposite direction: the command to walk back, for example south. It is needed to walk the path in reverse.

Buttons: Add…, Edit…, Remove, Load common directions and Close.

"Load common directions" adds the missing ones of this set: north (n), south (s), east (e), west (w), northeast (r), northwest (q), southeast (c), southwest (z), up (u), down (d), in (i) and out (o), each with its opposite. With the interface in Spanish the equivalent Spanish directions are loaded.

Creating and using paths

The paths window opens with F7 or with the paths command. It works like the aliases one, with the columns Name and Path.

The route is written with abbreviations. A number before an abbreviation repeats it. For example, 3n2ew means north, north, north, east, east, west. A number can have three digits at most, and the route cannot end with a number.

The editor has the fields Name and Path, and the "Show expansion" button, which tells how many steps the route has and which they are. When you accept:

  • It checks that every abbreviation exists in the directions of the MUD.
  • If some direction has no opposite, it warns that the path cannot be walked backwards.

To use a path, type an underscore and its name:

  • _square-tavern walks the path forwards.
  • _square-tavern -r walks it back: it reverses the order and replaces each direction with its opposite.

Recording a path

  1. Type paths iniciar. The status bar says "Recording path".
  2. Walk as usual, typing the directions or with movement mode. Each known direction is noted down and a short sound plays. Both the full command and the abbreviation work. The directions are sent to the MUD as always.
  3. If you make a mistake, paths ultima tells the last direction noted and paths ultima borrar removes it.
  4. paths grabado tells what you have so far.
  5. paths detener ends the recording and opens the new path dialog, with the route already written. You only have to give it a name.
  6. paths cancelar discards the recording, after a confirmation.

17. Sound and MSP

Omnimud plays wav, mp3 and ogg files, and can mix several sounds at once. Sounds come from three sources:

  • MSP (MUD Sound Protocol): the MUD asks for sounds with !!SOUND(...) lines and for music with !!MUSIC(...).
  • The sounds of your triggers and your Lua scripts.
  • The cues of the program itself: the click of the history, the cue when a direction is noted down and the cue when a link is opened.

About MSP:

  • MSP lines are never shown on screen, even when sound is off.
  • They are only recognised at the start of a line. That way another player cannot make your client play anything by writing the order on a channel.
  • The parameters volume (V), repeats (L), priority (P), continue (C), subfolder (T) and download address (U) are honoured. The name off stops the sounds or the music.
  • A name with wildcards, such as hit*.wav, picks at random among the files that match. A name without an extension is looked up as wav.
  • Priorities: while an effect is playing, another with a lower priority is not played; one with a higher priority replaces it. Music never overlaps other music. !!MUSIC with continue lets the music that is already playing carry on.

Sound folder. The sounds of the MUD are looked up in its sound folder: the one you set when editing the MUD or, if that is empty, data\sounds\name of the MUD. No name sent by the MUD can leave that folder.

Downloading. If a sound is missing and the MUD has given a download address, Omnimud downloads it to that folder and plays it. HTTPS is always tried first. Unencrypted HTTP is only used if you allow it in the options. If the download fails, there is no warning: that sound simply does not play.

The check boxes and the volume are in the Sounds tab of the options. Each game window only controls its own sounds.

18. GMCP: channels and the Actions menu

GMCP is a data channel between the MUD and the client, invisible to the player. If the MUD offers it, Omnimud turns it on by itself. The "Enable Telnet negotiation" option must be checked, as it is by default.

Channels to the Messages box. Channel messages that arrive through GMCP (Comm.Channel.Text) are added to the Messages box in the form "[channel] name: text". If the MUD also writes the same message as normal text, it is announced only once and it is not duplicated in Messages.

Actions menu. The MUD can tell what can be done at each moment, and Omnimud offers it as a normal menu:

  • Inventory (Char.Inventory package): each object is a submenu with its actions. A group of equal objects is a submenu of submenus. An object without actions is shown disabled: the menu also serves to know what you carry.
  • Exits (Room.Info package): one entry for each exit of the room. Choosing it sends that exit.

How to use it:

  • The Actions menu is the first one in the bar and opens with Alt+A. It is only visible while it has content. It appears and disappears without announcing anything, so as not to interrupt your reading.
  • The same sections are in the context menu of the Received box.
  • The menu is built at the moment you open it and does not change while it is open.
  • After you choose an action, the focus goes back to "Text to send".
  • If a list is very long, it is cut and ends with a disabled entry "… and N more".
  • When you disconnect, the menu is emptied.

Safety. The content of the menu is sent by the server, so Omnimud cleans and limits it. An action can only send text to the MUD. It goes through your aliases and paths, but the internal commands of the client are not obeyed from there, and it does not enter the history. A server cannot touch your configuration from a menu.

19. Message rules

Message rules decide which text of the MUD is copied to the Messages box: what people tell you, channels, whispers. They are managed from the launcher, Tools menu, "Message rules…" (Ctrl+R).

Rules are grouped in sets. Each MUD uses one set, or none. You choose it when editing the MUD.

Built-in sets. Omnimud ships four: Callandor, Simauria, Balzhur and Cyberlife, made for Spanish MUDs. In the list they are read with the text "(built-in)". They are read-only. To adapt one, use Duplicate… and work on the copy.

Buttons of the sets: New set…, Duplicate…, Rename… and Remove set. In the list of sets, Insert creates one, F2 renames it and Del removes it. If you remove a set, the MUDs that used it are left without rules.

A set is of one of two types. You choose it when you create the set, and change it in "Type of the set".

Patterns type. An ordered list of rules. Each rule has:

  • Pattern: a regular expression that is tried against each line.
  • Message template: the text that will go to Messages. $1, $2… are the groups of the pattern, ${name} a named group and $0 the whole match.
  • Channel, optional.
  • The check boxes "Case sensitive" and "Enabled".

Rules are tried in order and the first that matches wins. They produce one message per line. In the rule list: Insert adds, F2 or Enter edit, Del removes, Space enables or disables, and Alt+Up arrow and Alt+Down arrow move the rule. The same commands are in the buttons Add rule…, Edit rule…, Remove rule, Move up, Move down and Enable or disable.

Lua script type. A script sees the whole block of lines received, so it can capture messages of several lines. It reads om.lines or om.block and calls om.message(text) for each message. It cannot do anything else: it does not send, wait or play sounds. The four built-in sets are of this type.

  • The script is written in a box of several lines. Tab types a tab and Ctrl+Tab leaves the box.
  • "Save script" validates it. If there is an error, it tells the line and takes the cursor to it.
  • It has strict limits of time and instructions per block. If it fails during the game, you are warned only once and the game goes on. If it exceeds its limits three blocks in a row, it is switched off until the rules are reloaded.
  • Changing a set from Lua script to Patterns discards its script, after a confirmation.

The full contract is in the section "Reglas de mensajes" of API_LUA.md.

Testing. Type an example text in "Text to test against the set" and press "Test line". The result tells which rule matches and which message would come out, or "No message." With a script, it runs it on that block and lists the numbered messages. The editor of each rule also has its own "Run test" button.

A message that has already been read as text of the MUD is not read again when it enters Messages.

Warning: changes to the rules do not reach a game window that is already open. Close that window and connect again.

20. Options

Three levels and inheritance

Options exist at three levels: global, for each MUD and for each character.

  • The global options open from the launcher, with Ctrl+O.
  • In the game window, F9 opens the options of the level of that session: those of the character if you connected with a character, those of the MUD if you connected to a MUD without a character, and the global ones in a quick connect session. The title of the dialog tells whose they are.

At the MUD and character levels, the first thing in the dialog is a check box: "Use the global options" on a MUD, or "Use the options of the MUD" on a character.

  • With the box checked, that level has no options of its own and follows the level above. The tabs are shown disabled, with the inherited values.
  • With the box unchecked, that level has its own complete set of options. The first time you uncheck it, you start from a copy of the inherited values.
  • Inheritance works by block: either everything is its own or everything is inherited. Options are not inherited one by one.
  • A character without options of its own uses those of its MUD. If the MUD has none either, it uses the global ones.

The dialog has six tabs and a single set of buttons: OK, Cancel, Export… and Import… If a value is not valid, the program says so, switches to the tab of the field and gives it the focus. Changes are applied at once to the open game windows.

The check boxes of this dialog have no access key: reach them with Tab.

General tab

  • Screen reader: "Automatic (UI Automation)", "JAWS", "NVDA" or "None". Automatic by default. See Tips for screen readers.
  • Cursor in Received and Cursor in Messages. What the cursor does when text arrives: "Always go to the end of the text", "Keep it where it is" or "Go to the end only if it was already there". The third one by default.
  • History size (commands): from 1 to 10,000. 50 by default.
  • Language: Automatic, Español or English. It can only be changed in the global options. The change is applied the next time you start Omnimud.
  • Maximum lines in Received: from 100 to 1,000,000. 10,000 by default.
  • Prompt wait (milliseconds): from 0 to 60,000. 150 by default. It is the time Omnimud waits before showing text that arrived without a line break, such as a prompt. If your prompts are read in pieces, raise it.
  • Confirm before exiting. Checked by default.
  • Try to save the game before exiting. Checked by default. On closing it sends the save command and the quit command of the MUD.
  • Enable Telnet negotiation. Checked by default. Unchecked, Omnimud ignores the Telnet requests of the server. Without it there is no GMCP and no password mode.
  • Announce the text of the MUD. Checked by default.
  • Announce the messages. Checked by default.
  • Flash the window when text arrives in the background. Checked by default.
  • Check for updates when Omnimud starts. Only in the global options (it is the same switch as "Check for updates on startup" in the Tools menu of the launcher). Unchecked by default. See Updates.

Logs tab

  • Log type: "Do not save logs", "One per day" or "One per session". One per day by default.
  • Log folder, with the Browse… button. Empty means the default folder, data\logs. If the folder does not exist, the program offers to create it.

See Logs.

Sounds tab

  • Enable sound effects (MSP). It also governs the sounds of triggers and the cues of the program.
  • Play sound effects while the window is in the background.
  • Enable music (MSP).
  • Play music while the window is in the background.
  • Download sounds from the internet.
  • Allow unencrypted HTTP downloads when HTTPS fails. Unchecked by default. Some old MUDs only publish their sounds over HTTP.
  • Volume (0 to 100). 100 by default.

All the check boxes come checked, except the HTTP one.

Connection tab

It holds the proxy settings. They are explained in Proxy.

Appearance tab

  • Font: a list of the installed fonts. Consolas by default.
  • Size in points: from 4 to 200. 10 by default.
  • Change font…: opens the Windows font dialog.
  • Preview: a read-only box with a sample text in the chosen font.

The font applies to Text to send, Received and Messages. The colours of the text are those the MUD sends with ANSI codes: 16 colours, 256 colours and true colour.

Special characters tab

  • Use a character to send several commands at once, and Command stacking character. Off by default; the proposed character is the semicolon. With it, open door;north;close door sends three commands. To send the character itself, type it twice: ;;. Each part is treated as a complete command, with its aliases and paths.
  • Use a character to repeat a command several times, and Repeat character. Off by default; the proposed character is the hash sign. With it, 3#north sends north three times. The maximum is 50 repetitions.

Each character must be exactly one character, cannot be a digit or a space, and the two must be different.

21. Proxy

It is in the options, Connection tab. Most people do not need a proxy. Some company or school networks require one.

  • Proxy: "Do not use a proxy", "Use the proxy of the system" or "Enter it manually".
  • Proxy host, Proxy port and Proxy protocol (SOCKS5 or HTTP CONNECT). Only in manual mode.
  • Proxy user name (Alt+J) and New proxy password, empty to keep the current one (Alt+Q). Available in manual mode and in system mode. The stored password is never shown, not even as dots. Leave the box empty to keep it.
  • Delete the stored proxy password. Only enabled if one is stored.
  • Use the proxy for the MUD connection too. Unchecked by default.

How it is applied:

  • Sound downloads always follow the chosen proxy type. The update check honours it too.
  • The connection to the MUD only goes through the proxy if you check the last box. Otherwise it connects directly.
  • "Do not use a proxy" really is a direct connection, for downloads too.
  • "Use the proxy of the system" reads the proxy settings of Windows. It honours their exclusions and never uses a proxy for a MUD running on your own computer.
  • For the MUD, authentication is with user name and password. Integrated Windows authentication (NTLM or Kerberos) is not supported for the MUD connection.
  • The settings are read on every connection attempt. If you fix something in the options, pressing Reconnect is enough.

The proxy password is stored encrypted, is not exported and does not work on another computer. If the connection fails because of the proxy, the message says what happened and where to fix it: the proxy does not answer, it asks for or rejects the user name and password, it refuses to connect to the MUD, or the chosen protocol is not the one it speaks.

22. Logs

Omnimud can save everything that happens in each session to text files.

  • By default one file per day is saved. Change it in the options, Logs tab.
  • The files go in data\logs\name of the MUD\name of the character, or in the folder you choose.
  • The name of the file is the date, for example 2026-03-15.log. With "One per session" it also carries the start time.
  • They contain the text received, without colours, and the commands you sent. They are plain text in UTF-8, and text is always appended at the end.
  • When a session ends, a line "Session ended on…" is written.
  • Passwords are never written: neither what you send in password mode, nor the lines of the login script that contain %password.
  • Lines hidden by a trigger and the all_speak: marker are not written either.
  • If the file cannot be opened or written, you are warned once and the game goes on without a log.

Logs stay on your computer. Omnimud does not send them anywhere and does not include them in error reports.

23. Import and export

Omnimud exchanges data in text files with the .omnimud extension. They are useful for backups, for moving your configuration to another computer or for sharing it with someone else.

What can be exported:

  • A MUD (launcher, Ctrl+E): its connection data, its login script, its directions, its movement keys, its options and its message rule set, with the Lua script if it has one. The program asks whether you also want to include its characters.
  • A character (launcher, Ctrl+Shift+E): its aliases, triggers, paths, movement keys and options.
  • A single list of aliases, triggers or paths: the Export… button of each list window.
  • A set of options: the Export… button of the options dialog.

Passwords are never exported: neither those of the characters nor the proxy one. The proxy user name is exported. Your personal information is not exported either.

Importing:

  • In the launcher, Ctrl+I imports any .omnimud file. A character file is imported into the MUD you have selected in the tree.
  • In the aliases, triggers and paths windows, the Import button offers "From file…" and "From another character…", which copies straight from another of your characters.
  • In the options dialog, Import… loads the values into the dialog. They are not saved until you press OK.

Conflicts. If some element of the file already exists, the "Elements that already exist" dialog appears, with a list of check boxes. Check the ones you want to overwrite; the unchecked ones are skipped and stay as they are. There are the buttons "Overwrite all", "Skip all", "Import" and Cancel. A status line tells how many will be overwritten and how many skipped.

At the end, the program sums up the result: how many elements were added, overwritten, skipped and how many failed. Importing is safe: a file that is damaged, too large or created by a newer version is rejected with a clear message and changes nothing.

24. Portability

All the data of Omnimud is in the data folder next to Omnimud.exe:

  • data\omnimud.db: the database with the MUDs, characters, aliases, triggers, paths, rules and options.
  • data\master.key: the key used to encrypt the passwords.
  • data\logs: the session logs.
  • data\sounds: the sounds of each MUD.

Omnimud does not use the Windows Registry. To take the program to another computer or to a USB drive, copy the whole Omnimud folder, with its data folder. To make a backup, copy the data folder while Omnimud is closed.

Passwords. The saved passwords, of the characters and of the proxy, are encrypted and tied to your Windows user. When you take the folder to another computer, or to another Windows user, they cannot be decrypted. There is no error: the program behaves as if no password were saved, so none is sent when connecting. Edit each character and type its password again. Everything else travels intact.

A folder without write permission. If the folder of the program cannot be written to, for example inside "Program Files", Omnimud stores the data in your user profile, in %AppData%\Omnimud. In that case the installation is no longer portable. It is best to keep Omnimud in a folder where you can write.

To update a portable installation, unzip the new version over the previous one, or into a new folder to which you then copy your data folder.

25. Updates

Omnimud can check whether there is a new version, but it never downloads or installs anything by itself.

  • Check for updates now: launcher, Tools menu. It checks right away and tells you the result, whether there is a new version, you already have the latest one, or the check fails.
  • Check for updates on startup: a check box in the same menu, which is also in the global options, General tab. It is off by default. If you turn it on, the check runs in the background at startup. It only tells you if there is a new version. A network failure at startup is silent.

What exactly the check does:

  • It makes a single anonymous query to the public GitHub API. It sends none of your data.
  • It honours the configured proxy.
  • If there is a new version, it shows a dialog with the version number, the release notes and two buttons: "Open the download page", which opens the page of that release on GitHub in your browser, and "Close".

You do the download and the installation yourself, as in the initial installation. Your data folder is kept.

26. Suggestions, errors and privacy

In the Help menu, both in the launcher and in the game window, you will find "Send suggestion…" and "Report an error…". Both entries open the same dialog, with the type already chosen.

The report dialog

  • Type: Error or Suggestion.
  • Description: tell what happened or what you propose. If it is an error, say what you were doing, what you expected and what happened.
  • Include diagnostic data: a check box. It adds the version of Omnimud, of Windows and of .NET, the architecture, the language of the interface and the chosen screen reader mode. Nothing else.
  • Title: the title of the issue or the subject of the message. It is composed from the first line of the description and you can change it.
  • Preview of what will be sent: an editable box with the exact text that will be sent. You can read all of it and correct or delete anything you want before sending.

Buttons:

  • Open in GitHub: opens in the browser a new issue, already filled in, in the Omnimud repository. A GitHub account is required, and you submit the issue yourself from the page. Issues are public.
  • Send by e-mail: opens your mail program with the message already written. You send it yourself. Before that, it asks whether you want to sign it with your personal information.
  • Copy to clipboard: copies the report so that you can paste it wherever you want.
  • Personal information…
  • Cancel.

If the report is too long to fit in the link, the text in the link is trimmed and the full report is copied to the clipboard. Paste it yourself into the page or the message.

Privacy

  • Nothing is sent automatically. Omnimud only opens your browser or your mail program. You do the sending, after seeing the text.
  • Reports never include passwords, text of the MUD, session logs, host names of your MUDs or character names.
  • Folder paths that contain your Windows user name are replaced with %USERPROFILE%.
  • Omnimud has no telemetry and no usage statistics. The only connections it makes are: to the MUD, to the sound download address given by the MUD if you allow it, and to GitHub when you check for updates.

Unexpected error

If something fails inside the program, a dialog titled "Unexpected error" appears, with the description of the failure and three buttons:

  • Report this error…: opens the report dialog with the details already included in the preview.
  • Copy details: copies the technical details to the clipboard.
  • Continue: closes the dialog.

The focus starts on Continue; the details are in a text box that you read with the arrow keys. If more errors happen while the dialog is open, no more dialogs appear: their details are added to the same box, numbered.

The program does not close: you can keep playing. If the same error happens again, please report it.

27. Personal information

It opens from the launcher, Tools menu, "Personal information…", or from the button with the same name in the report dialog. It has two fields, both optional:

  • Name.
  • Email address.

What it is for and what it is not for:

  • It is only used to sign a report when you send it by email, and it asks you first.
  • It is not sent anywhere by itself.
  • It is not included in GitHub issues, which are public.
  • It is not exported in .omnimud files.

You can leave both fields empty and use Omnimud normally. To delete the data, empty the fields and accept.

28. Tips for screen readers

How Omnimud talks to your screen reader:

  • With the "Screen reader" option set to Automatic (UI Automation), which is the default, Omnimud sends UI Automation notifications. Current versions of NVDA, JAWS and Narrator understand them, without anybody's libraries. If the notification cannot be raised, it falls back to the JAWS and NVDA libraries in the dlls folder.
  • With JAWS or NVDA, it talks straight to that screen reader through its library and does not use UI Automation.
  • With None, Omnimud announces nothing. Your screen reader still reads whatever you walk through with the cursor.
  • Lines that arrive together are grouped into a single announcement, so that the screen reader is not flooded and no text is lost.

If things are read twice:

  • Try changing "Screen reader" from Automatic to the name of your screen reader, or the other way round. That way Omnimud uses a single route.
  • If your screen reader already reads the new text of the window by itself, uncheck "Announce the text of the MUD" and, if needed, "Announce the messages".
  • A channel message that arrives through GMCP and also as text is already announced only once. If you hear it repeated, tell us in an error report.

If nothing is read, check in this order:

  1. That the game window is in the foreground. Text is only announced while the window is active.
  2. That "Mute screen reader" (Ctrl+M) is not checked in the Tools menu.
  3. That silent mode (F8) is not checked.
  4. That "Screen reader" is not set to None, and that "Announce the text of the MUD" is checked.
  5. If you use an old version of your screen reader, one that does not understand UI Automation notifications, choose JAWS or NVDA instead of Automatic.
  6. That the dlls folder is still next to Omnimud.exe.

If the cursor does not move, or moves when you do not want it to. This is the "Cursor in Received" or "Cursor in Messages" option. By default, the cursor only jumps to the end if it already was at the end. To follow new text again after reviewing, press Ctrl+End inside the box. If you prefer the cursor always to go to the end, choose "Always go to the end of the text". If you never want it to move, choose "Keep it where it is".

Other tips:

  • When Received or Messages get the focus, the name of the box and only the line of the cursor are spoken, not the whole text.
  • The input box carries no help text: that way nothing extra is read each time it gets the focus.
  • To review conversations you do not need to leave the input box: use Ctrl+1 to Ctrl+0.
  • Alt+S stops speech when the MUD writes too much.

NVDA

  • Omnimud has been tested with NVDA. UI Automation announcements work, and screens of many lines are read in full.
  • Leave the option on Automatic. Choose "NVDA" only if something is not read.
  • To diagnose a reading problem, set the NVDA log to the "Input/output" level: NVDA menu, Preferences, Settings, General, Logging level. Then reproduce the problem and open the log viewer with NVDA+F1, or from the Tools menu of NVDA. The lines that start with Speaking [...] tell what was spoken and in which order.
  • If you send a report, you can paste those lines. Check first that they contain nothing private.

JAWS

  • With a current version of JAWS, leave the option on Automatic.
  • If the text of the MUD is not announced, choose "JAWS" in the "Screen reader" option. Omnimud will then speak through the JAWS library.
  • If JAWS repeats the text, try the other route, as explained above.
  • Received and Messages are normal edit boxes: walk through them with the PC cursor and the usual reading keys.

29. Troubleshooting

  • It does not connect. Read the error message: it tells the reason. Check the host and the port. If you use TLS, check that that port of the MUD is the encrypted one. If the failure is about the certificate, see Validate the server certificate. If it mentions the proxy, see Proxy.
  • Accented letters look wrong. Change the encoding of the MUD. The most usual ones are utf-8 and iso-8859-1.
  • It does not log in by itself. Check that you connect with a character, that it has its password saved and that the login script fits what the MUD asks. If you have changed computers, type the password again.
  • F3 or F4 are disabled. Type the save and quit commands when editing the MUD.
  • F5, F6 or F7 say that a character is required. You are in a quick connect session or connected to a MUD without a character. Create a character and connect with it.
  • A path says there are no directions. Open Tools, "Directions for paths", and press "Load common directions".
  • A path cannot be walked in reverse. One of its directions has no opposite direction. Edit it in the directions of the MUD.
  • A trigger does not fire. Check that it is enabled and that you have not typed -triggers. Use the Test button with a line copied from Received. Remember that a line trigger only sees complete lines: if the text comes spread over several, mark it as Multiline.
  • A trigger gets into a loop. Type -triggers to stop everything, fix the trigger and type +triggers.
  • Prompts are read late or in pieces. Adjust "Prompt wait" in the options.
  • The arrows do not browse the history. Movement mode is on. Use Ctrl+Up arrow and Ctrl+Down arrow, or turn it off with F2.
  • The numeric keypad types numbers instead of moving. Turn movement mode on with F2 and check that Num Lock is on.
  • There is no sound. Check the Sounds tab and the volume. If the MUD downloads its sounds over HTTP, check the box that allows it. Check that the files are in the sound folder of the MUD. A failed download gives no warning.
  • The Messages box is empty. Assign a message rule set to the MUD, or create your own. If the box is not there, look in the View menu, "Show messages panel".
  • I changed the message rules and nothing happens. Close the game window and connect again.
  • F1 says the help file was not found. The docs folder next to Omnimud.exe is missing. Unzip the complete zip again.
  • The program does not save anything. The folder cannot be written to. See Portability.
  • "Unexpected error" appears. Press "Report this error…" or "Copy details", and then Continue. See Unexpected error.
